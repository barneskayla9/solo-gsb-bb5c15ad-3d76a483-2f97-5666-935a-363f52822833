# 线下场馆失物认领网页

一个自托管的「失物招领 / 认领」小系统：工作人员登记物品并核对认领，访客公开浏览、
提交辨认答案并获得**不可猜测的查询凭证**，获选人凭**一次性交还码**完成当面交还。

技术栈：**Python 3.12 标准库（零第三方依赖）+ SQLite + 浏览器页面**。
不使用任何 pip 第三方包，镜像构建无需联网安装依赖。

---

## 功能与权限

| 角色 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| 访客 | 浏览**公开描述**；提交辨认答案 + 联系方式，取得一次性查询凭证；凭凭证只查**本人**进度；**凭原查询凭证撤回本人认领**；获选后凭凭证取得一次性交还码 | 看不到私密辨认特征、他人答案、他人联系方式、物品保管状态明细 |
| 工作人员（口令登录） | 登记物品（公开描述 + 私密辨认特征）、查看全部申请与联系方式（**含访客撤回时间**）、撤下/恢复物品、选定一份认领、重发交还码、**误选改判**、核码登记交还 | — |

关键业务规则（均由数据库事务保证）：

- **并发确认最多成功一次**：同一物品多个工作人员同时「选定」，只有一份申请获选，
  其余待核对申请自动标记为「未获选」。
- **已撤下 / 已交还物品拒绝新申请**；撤下时未处理申请一并标记未获选。
- **一次性交还码**：8 位数字 + 后台随机签发；获选人凭查询凭证查看；
  工作人员核码成功后物品立即变为「已交还」。
- **重复核码无效**：同一码重复提交、两枚码并发核销，都只能成功一次。
- **过期可重发**：工作人员重发后旧码立即失效（查询页与核码均拒绝旧码）。
- **误选可改判**：工作人员发现认领误选时，只要物品**仍保管中、尚未交还**，
  即可在原获选申请页指定同一物品的另一份「未获选」申请并填写**更正理由**完成改判：
  原申请变为未获选、其全部未核销交还码立即失效，目标申请变为已获选并获得一枚
  新的一次性交还码；双方原有查询凭证仍只显示本人最新状态，新码仅对新获选人和
  工作人员可见。更正记录保存申请双方、理由与时间，供工作人员追溯。
  物品已撤下/已交还、目标不属同一物品或非未获选、原申请已非获选、理由为空，
  均拒绝且不改动任何状态；改判表单携带物品单调递增版本号（乐观锁），与重发、
  撤下、核码或另一改判并发时，仅一次符合条件的状态变更生效，另一方收到
  「请刷新页面确认最新状态」的提示且不写入任何记录。
- **访客可撤回本人认领（本轮新增）**：访客在查询页凭**原查询凭证**即可撤回，
  无需额外口令或新凭证。
  - 撤回后凭证仍可查询，状态显示为「已撤回」（含撤回时间）；不再显示交还码、
    不会被重新选定。**重复撤回只显示已撤回，不重复写入**（撤回时间不变）。
  - **待核对 / 未获选**申请撤回：仅改变本人状态，不影响物品与他人。
  - **已获选**申请撤回：在单个事务内原子地把本人置为「已撤回」、**作废其全部
    未核销交还码**；物品**仍保管中**时，将同物品其余「未获选」申请恢复为
    「待核对」并重新接受新申请（**已主动撤回的申请不恢复**）；物品**已撤下**
    时只作废旧码，不恢复申请、不开放提交。
  - 物品**已交还**时拒绝撤回任何申请，给出明确提示且不改动状态。
  - 撤回与工作人员选定 / 改判 / 重发 / 撤下 / 核码并发时，一律以**提交时最新
    已提交状态**裁决：写事务串行 + 条件式原子更新，失败方收到明确状态提示，
    不留下可用旧码、不产生双获选、不发生部分更新。撤回获选申请会推进物品
    版本号，使页面版本过期的工作人员表单收到「请刷新」提示。
- 数据库只存查询凭证与交还码的 **SHA-256 哈希**；交还码另以**认证加密密文**存储，
  仅在「持凭证的获选人查询页 / 工作人员详情页」解密显示；HMAC 密钥保存在数据卷，
  不随镜像分发。

## 所需配置（环境变量）

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `STAFF_PASSWORD` | 生产必填 | `change-me` | 工作人员登录口令。使用默认值时容器会打印警告。 |
| `HOST_PORT` | 否 | `8080` | 宿主机映射端口（容器内固定 8080）。 |
| `HANDOVER_CODE_TTL` | 否 | `86400` | 交还码有效期，单位秒（默认 24 小时）。 |
| `LF_DATA_DIR` | 一般无需改 | `/data` | SQLite 数据库与密钥目录（Docker 卷挂载点）。 |

## 一条命令启动

```bash
# 可选：复制并修改配置
cp .env.example .env
#   编辑 .env，把 STAFF_PASSWORD 改成强口令

docker compose up -d --build
```

停止 / 重启 / 查看日志：

```bash
docker compose down          # 停止（数据保留在 Docker 卷 lostfound_data 中）
docker compose restart
docker compose logs -f
```

## 使用流程

1. 工作人员打开 `/staff/login`，输入 `STAFF_PASSWORD` 登录。
2. 在登记台录入物品：**公开描述**（访客可见）与**私密辨认特征**（仅工作人员可见）。
3. 访客在首页看到公开描述，打开物品提交「辨认答案 + 联系方式」，
   页面**仅此一次**显示查询凭证，访客自行保存。
4. 访客在 `/query` 粘贴凭证查看本人状态：待核对 / 已获选 / 未获选 / 已撤回。
   访客若放弃认领，可在该页直接「确认撤回认领」（凭原凭证）：
   - 待核对 / 未获选撤回只改变本人状态；获选后撤回会作废旧交还码，物品仍保管中时
     其他未获选申请恢复待核对、物品重新接受新申请；已交还则无法撤回。
5. 工作人员在物品详情页比对答案与私密特征，点「选定此申请并签发交还码」：
   - 其他待核对申请立即变为「未获选」；
   - 获选人在查询页看到一次性交还码及有效期。
6. 获选人到场出示交还码，工作人员在「核销交还码」页输入 8 位码：
   - 成功 → 物品标记「已交还」，拒绝一切新申请；
   - 重复 / 过期 / 已重发的旧码 → 拒绝并给出原因；
   - 码过期 → 工作人员可在申请详情页「重发新码」，旧码立即失效。
7. **误选改判（本轮新增）**：交还前工作人员若发现选错获选人，打开原获选申请详情页，
   在「误选改判」卡片选择同一物品的另一份未获选申请、填写更正理由后提交：
   - 原申请立即变为「未获选」，其所有未核销交还码立即失效（旧码在核码页会被拒绝）；
   - 目标申请变为「已获选」并签发一枚新的一次性交还码，新获选人凭其原有查询凭证即可查看；
   - 物品详情页与相关申请详情页展示「改判记录」（原申请、目标申请、理由、时间）供追溯；
   - 物品已撤下/已交还、目标不属于同一物品或不是未获选、原申请已非获选、理由为空，
     均拒绝且不改动任何状态；与重发、撤下、核码或另一改判并发时，只有一次状态变更生效。

## 数据持久化与初始化

- 数据位于 Docker 卷 `lostfound_data`（容器内 `/data`）：
  - `lostfound.db`：SQLite 数据库（WAL 模式）；
  - `secret.key`：会话签名与交还码加密密钥（自动生成，权限 600）。
- 数据库表由 `lostfound/schema.sql` 在容器启动时**幂等初始化 / 升级**
  （`CREATE TABLE IF NOT EXISTS`），不会破坏已有数据。
- 备份：停服后复制卷内 `lostfound.db`（及 `-wal`/`-shm`，或先 `docker compose stop`）。

不使用 Docker 本地运行（需要 Python 3.11+）：

```bash
export LF_DATA_DIR=./data STAFF_PASSWORD=please-change-me PORT=8080
python -m lostfound.init_db
python -m lostfound.app
```

## 目录结构

```
.
├── Dockerfile                 # 运行环境（python:3.12-slim，无第三方依赖）
├── docker-compose.yml         # 一条命令启动 + 数据卷 + 健康检查
├── docker/entrypoint.sh       # 启动前初始化数据库
├── .env.example               # 配置模板
└── lostfound/
    ├── app.py                 # WSGI 应用 / HTTP 服务 / 路由 / 会话 / CSRF
    ├── db.py                  # SQLite 连接、WAL、IMMEDIATE 事务
    ├── repository.py          # 数据访问与并发安全的业务事务
    ├── security.py            # 随机凭证、哈希、签名 Cookie、AEAD 加解密
    ├── render.py              # 页面渲染（全部动态值 HTML 转义）
    ├── schema.sql             # 建表脚本（幂等）
    └── init_db.py             # 数据初始化入口
```
